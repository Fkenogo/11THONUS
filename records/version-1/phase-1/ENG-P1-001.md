## 3. Purpose

`ENG-P1-001` established the Firebase and shared-platform foundation every later domain service depends on: safe environment/config loading, a Firebase client SDK bootstrap (App/Auth/Firestore/Storage/App Check), a Firebase Admin SDK bootstrap, and the `europe-west1` region constant — the first work package of Phase 1 and the first to touch live Firebase infrastructure in this programme (per the [Version 1.0 Engineering Authorization Record](../../../docs/00-governance/version-1-engineering-authorization-record.md) §10).

In scope: client/admin SDK bootstrap and region-scoped configuration (planning-level). ## 17. Lessons Learned

- Live-project provisioning is a Founder/Engineering-Lead-owned action, not a coding-agent action — the Technical Review's central governance finding was that this is required before `Complete`, but not before Technical Approval (Definition of Done §2 item 6 precedes items 7–8); this sequencing held throughout closure without rework.
- A GCP project-ID naming-format constraint (must start with a lowercase letter) blocked the first provisioning attempt — a platform format rule, not a decision-dependency or availability conflict; caught immediately and retried with corrected IDs rather than escalated as a blocker.
- The Founder's own Definition-of-Done gates (possession, Preview Review) took multiple session iterations to correctly sequence relative to the coding agent's merge-execution authority — resolved by grounding the distinction directly in Git Workflow §3's text ("This is the single point at which the Founder takes possession of the change") rather than inferring it.
